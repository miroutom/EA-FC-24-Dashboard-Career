# Prompt для Codex — Leicester City Analytics (Auto MVP v0.2)

Создай **полноценное локальное веб-приложение Leicester City Analytics** на основе документа `Leicester_City_Analytics_Auto_MVP_Spec_v02.md` в корне репозитория. Это основной источник требований; перечитай его перед проектированием.

## Суть продукта

Мы совместно играем карьеру EA FC 24. Нужен аналитический дашборд по мотивам скриншотов RespectTheJeff: Summary, Squad Overview/Table/Updates, подробная выдвижная панель игрока, сравнение игроков, сезонная и карьерная статистика. **Принципиальное требование — после первоначальной настройки НЕ делать скриншоты и НЕ вводить вручную статистику после каждого матча.** Допускаются только необязательные `notes`.

Данные собираются локально из FC 24 через xAranaktu Live Editor + Lua; Python watcher импортирует снимки, сохраняет их в SQLite, вычисляет валидные изменения между снимками, React обновляет дашборд. Несколько разных карьер и сейвов должны быть изолированы.

Первый исторический источник: `leicester_rebuilt_with_career_totals.xlsx`, Leicester City 2023/24–2027/28. Импортируй **только лист `Все сезоны`**, НЕ сезонные дубли и НЕ `За всю карьеру`; агрегаты считай на backend. Исходная статистика неполная (скриншоты), учитывай `coverage`.

## Очень важная граница достоверности

Документированы `GetPlayersStats()` с накопленными `app/goals/assists/yellow/red/avg/...` и обработчики CareerModeEvent, но это **не доказывает наличие** матча, соперника, счёта, xG, владения, минут или индивидуальной послематчевой оценки. Не выдумывай эти поля, не подставляй тестовые значения в production и не называй изменение между двумя снимками «отдельным матчем», пока это не доказано.

## Порядок реализации

1. Сначала **Phase 0 POC**: read-only `diagnostic.lua`, `event_probe.lua`, Python diff-tool, docs/capability-matrix.md и инструкция реальной проверки через EA FC 24 Windows.
2. Затем модели и миграции SQLite; multiple careers/save bindings; отдельные исторические totals, накопительные Live snapshots и derived deltas, без двойного счёта.
3. Импорт Excel/CSV (preview → validate → commit), идемпотентность и конфликты.
4. FastAPI REST endpoints, реальные агрегации, React/Tailwind/shadcn dashboard и таблицы, player drawer, compare, синхронизация/статус.
5. Локальный file watcher для `snapshot_v1` JSON, атомарная ingestion, дедупликация, rollback/season rollover handling, sync health, optional notes.
6. Unit/integration tests, README, Windows Live Editor setup, запуск без Docker и без облачных сервисов.

## Стек

React + TypeScript + Vite + Tailwind + shadcn/ui + Recharts + TanStack; Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic + Pydantic 2; SQLite; Lua Live Editor; pytest + Vitest. Интерфейс на русском, тёмный, современный, desktop-first, с аккуратными синими акцентами.

## Приёмка

- Две карьеры независимы.
- Excel загружается без задвоений, карьерные итоги реально совпадают с суммой сезонов.
- Статистика по сезонам, турнирам (если источник доступен) и всем годам, графики и игроки — из БД.
- Повторный Lua snapshot не увеличивает totals.
- Понижение counters, смена сезона, пропуск матчей и откат save не превращаются в фальшивые матчи/голы.
- Нет ручной загрузки после каждого матча; есть необязательные notes.
- Все неподтверждённые возможности явно помечены `NOT_TESTED`/`UNAVAILABLE` до реальной проверки.

**Если в среде Codex нет EA FC 24/Live Editor:** реализуй код + тесты + manual validation, но НЕ утверждай, что Live интеграция реально испытана. Отчёт должен чётко разделять «реализовано», «проверено тестами» и «требует проверки в игре».

Работай по этапам и выполняй доступные проверки после каждого. В конце укажи команды локального запуска, результаты тестов, ограничения и точную последовательность проверки коллектора в Windows.
