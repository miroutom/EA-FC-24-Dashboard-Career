# Задание Codex на Windows: загрузка карьеры и блокировка небезопасного сбора

Сначала прочитай [разбор 12 дампов](docs/crash-investigation-2026-10-29.md).
Пользователь сообщает: игра каждый раз закрывается при загрузке сохранения.
Не объявляй OCR, callbacks, конкретную таблицу или повреждение save установленной
причиной. Все дампы показывают одну инструкцию FC24, но источник её состояния
ещё неизвестен. Не представляй отключение сборщика как исправление сейва.

## 1. Подтянуть ветку, сохранить локальные изменения

Репозиторий: https://github.com/miroutom/EA-FC-24-Dashboard-Career
Исходный Windows-код: `fix/windows-live-context`, коммит `b2b8584`.
Ветка с разбором и защитными правками: **`fix/live-editor-crash-triage`**.

Используй существующий checkout. Если его нет, клонируй репозиторий в отдельный
каталог. На чистом рабочем дереве:

```powershell
git status --short --branch
git remote -v
git fetch origin
git switch --track -c fix/live-editor-crash-triage origin/fix/live-editor-crash-triage
git log -1 --oneline
```

Если локальная ветка уже есть — переключись на неё и используй `git pull --ff-only`.
Не делай reset, clean, force push и не теряй незакоммиченные изменения. Проверяй
exit codes. Маковский SSH-ключ не предполагается установленным на Windows.

## 2. Сохранить доказательства до экспериментов

При закрытой игре/LE и остановленном dashboard скопируй реальные файлы карьеры
и весь DATA_DIR в отдельный backup. Найди фактическое расположение saves, учитывая
перенос Documents/OneDrive. Не угадывай слот по имени/времени и не перезаписывай
оригиналы. Запиши SHA-256, размеры и времена good/bad saves; их байты не публикуй.

Сохрани актуальные LE logs и dumps. Для offline-анализа используй
`scripts/inspect_minidumps.py`; отчёт положи в `data/preflight/`, который игнорируется
Git. Дампы содержат память процесса: не коммить их и не отправляй в сторонние сервисы.

## 3. Инвентаризация Windows-установки

Из известных путей установки получи SHA-256, FileVersion/ProductVersion, размер
и время для **фактически загружаемых** FC24.exe, Engine.BuildInfo.dll и FCLiveEditor.DLL.
Пример для одного найденного файла:

```powershell
$BinaryPath = 'C:/actual/path/FC24.exe'
Get-FileHash -Algorithm SHA256 -LiteralPath $BinaryPath
(Get-Item -LiteralPath $BinaryPath).VersionInfo |
    Select-Object FileVersion, ProductVersion
```

Уточни установленный Steam build/manifest, список активных модов и что именно
менялось при downgrade. В дампе FC24.exe имеет PE timestamp июля 2024, а
Engine.BuildInfo.dll — марта 2025. Проверь, допустим ли такой состав для фактической
установки, без вывода о несовместимости только по timestamp.

Сверяй LE с официальными материалами автора для FC24, а не другой игры.
Не подменяй EXE/DLL, не меняй античит, не запускай автоматическое восстановление
всех файлов игры и не обновляй сборку ради догадки. Сначала нужен проверяемый
инвентарь; изменение сборки может затронуть совместимость модов и saves.

## 4. Исключить запуск нашего сбора

- В `.env` и переменных окружения отключи `SCREENSHOT_WATCHER_ENABLED`. Не печатай
  весь `.env`. Во время baseline останови backend/OCR обычным способом.
- Найди только связанные с LCA скрипты автозапуска в фактической установке LE.
  Зафиксируй их пути/содержимое, перенеси копии из autorun в локальный backup.
  Не удаляй остальные моды или чужие handlers.
- В актуальной ветке diagnostic/event probe/collector выключены. Старые значения
  `manual_capture_ack`, `LCA_UNSAFE_EVENT_PROBE_ACK` и verification flags не включают
  новые entrypoints. Не снимай блокировку ради эксперимента на рабочей карьере.
- Замена файлов не снимает callbacks из уже работающей VM. Полностью закрой игру
  и LE штатно; следующая проверка начинается с нового процесса.
- Проверь, что не используются прежние копии скриптов из другого каталога.

## 5. Разделить причины загрузки на тестовых копиях

Подготовь отдельные копии known-good и affected save. Для каждого запуска запиши
точный набор game/LE/mod versions, отсутствие LCA/OCR, выбранную копию и результат.

1. При неизменной сборке и модах проверить known-good copy и affected copy с
   отключёнными LCA/OCR. Не делать новых сохранений поверх исходников.
2. Если возможен штатный запуск этой сборки без LE, сравнить те же копии без LE.
   Зависимость save от модов учитывать: изменение модов не должно быть скрытой
   второй переменной. Если сопоставимый сценарий невозможен, так и записать.
3. Отдельно проверить создание, сохранение и загрузку новой одноразовой карьеры
   без сбора. Не возвращать Lua после одного успешного reload.

Не нужны десятки повторных вылетов одного save. Если affected падает при known-good,
который загружается в той же конфигурации, проблема зависит от save/его совместимости;
это ещё не доказывает, кто его изменил. Если проблема есть и на новых saves, сначала
разбирай game/LE/mod environment. При изменении подписи падения анализируй новый дамп.

## 6. Углубить анализ дампа локально

Если установлен WinDbg, открой последний `.mdmp`, настрой путь к **точному**
FC24.exe из этого запуска и выполни:

```text
.symfix
.exepath C:\actual\path\to\game
.reload
.ecxr
!analyze -v
r
kv
lmvm FC24
lmvm FCLiveEditor
lmvm Engine
u @rip-20 @rip+40
```

Microsoft symbols могут помочь системным модулям; приватные символы EA не
предполагаются доступными. Если нужны другие module names, возьми их из `lm`.
Не используй несовпадающий бинарник и принудительное игнорирование mismatch.
Нужны реальная faulting instruction, доступные unwind frames и контекст объекта.
Не выдавай найденные на стеке адреса за доказанный call stack.

## 7. Дальнейшая автоматика

Требование остаётся прежним: автоматический сбор, без ручной загрузки скриншотов.
OCR может читать архивные картинки отдельно, но не закрывает P2.

`GetSaveUID` может писать в БД, поэтому он удалён; используй явный instance binding.
Не добавляй скрытые DB setters, запись save и опрос непроверенных getters.
Дальнейший источник нужно исследовать отдельно: подтверждённое отложенное чтение
в разрешённом контексте LE либо документированный parser копии save вне процесса.
Пока такого источника и повторяемых reload checks нет, честный статус — **BLOCKED**.
Смена callback на таймер сама по себе не доказывает безопасность.

## Результат работы агента

Сохрани локально `data/preflight/recovery-report.md`: commit, хеши бинарников/saves,
конфигурации запуска, таблица выполненных проверок, свежая crash signature,
подтверждённые факты и оставшиеся гипотезы. В чат дай короткий результат.
Кодовые правки проверь backend/frontend тестами и миграциями; новые game checks
нельзя заменять pytest или synthetic data. Не отмечай save восстановленным,
пока его копия действительно не загружается; не отмечай автоматику работающей
без unattended capture и последующего сохранения/загрузки.
